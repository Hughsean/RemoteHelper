# 采样历史持久化与同步方案

设计稿。参考本地 Argus 源码的日文件、崩溃恢复和趋势图交互；RemoteHelper 首期记录主机级与单 GPU 指标。

## 1. 摘要

服务端在等待网络和打开监听端口之前启动采样。有客户端查看监控时，按有效请求中最细的粒度采样；没有客户端时默认每 5 秒采样。每次采样形成一个原始记录点，按 UTC 天归档。WAL 保存待封存记录，封存块采用列式编码、定点量化、差分和 zstd。放大时间窗口时，趋势图按时间桶显示均值，缩回去可查看原始采样点。

客户端按天增量复制已发布的数据包，用未封存尾部和实时采样补足最新的区间。服务端缺口、尚未同步和已过保留范围分别显示。已缓存历史支持离线查询。远程历史设置由有权限的客户端修改，配置写入成功后生效。

## 2. 现状与约束

- [监控任务](../../crates/server/src/monitor.rs)在 10 秒无人读取后跳过采样。[状态请求](../../crates/server/src/handlers/system.rs)更新全局刷新间隔，并在请求时生成时间戳。采样发生时间与读取时间需要分开。
- 网络字段当前直接使用 sysinfo 本次刷新得到的字节差，作为 B/s 使用前需按实际采样间隔换算。趋势图当前绘制 CPU、内存比例和 GPU 使用率，已有[折桶](../../app/src/views/trend/aggregation.rs)和[阶梯线](../../app/src/views/trend/step.rs)。
- [现有协议](../../crates/common/src/lib.rs)使用带长度前缀的加密 JSON 帧。服务端请求缓冲为 10 KiB，客户端常规请求使用 64 KiB 响应缓冲。[连接超时](../../crates/server/src/server.rs)覆盖整条连接的生命周期；[客户端全局连接](../../crates/client/src/requests.rs)一次只执行一个请求。
- [配置](../../crates/server/src/config.rs)随进程启动加载，[主流程](../../crates/server/src/main.rs)先等待网络再启动监控。现有握手由服务端认证客户端，历史缓存和远程设置需要可验证的服务端身份。

## 3. 目标与范围

1. 服务端无人连接时仍记录；磁盘异常时维持实时监控，并报告丢失区间。
2. 原始采样可按区间查询、断点同步、离线查看，缓存按天管理。
3. 记录配置和保留策略可在线修改；清除服务端历史、按设备拆分、进程历史、外部时序存储和磁盘加密留待后续。

## 5. 采样与记录

### 5.1 时钟和样本身份

| 字段 | 来源与用途 |
| --- | --- |
| wall_ms | Unix 毫秒时间，作为 UTC 坐标；无效时间单独处理 |
| tick_ms | Windows GetTickCount64，包含睡眠和休眠，用于判断两次采样间经过的真实时间 |
| awake_ms | Windows QueryUnbiasedInterruptTime 换算成毫秒，包含系统处于运行状态的时间 |
| boot_id | 可选的 16 字节开机标识，用于跨进程区分服务重启和系统开机变化 |
| session_id + sample_seq | 每次进程启动生成随机会话 ID，采样序号在会话中递增，用于去重和识别丢点 |
| period_ms | 本次采样使用的目标周期，用于区分短时抖动、停顿和节奏切换 |

Windows 在服务启动时通过运行时动态加载的 `NtQuerySystemInformation(SystemBootEnvironmentInformation)` 读取 `BootIdentifier`，校验返回状态和 GUID 字段长度，通过后缓存用于本次进程。API 不可用、调用失败或返回全零 GUID 时将 `boot_id` 记为空。原生接口和结构可能随系统版本变化，各固件及电源模式以实测为准。其他平台可省略 `boot_id`，继续使用可用的单调时钟。 [Microsoft NtQuerySystemInformation](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntquerysysteminformation) · [SYSTEM_BOOT_ENVIRONMENT_INFORMATION](https://ntdoc.m417z.com/system_boot_environment_information) · [Microsoft Windows Time](https://learn.microsoft.com/en-us/windows/win32/sysinfo/windows-time)

跨进程时两侧均有有效标识且不同，优先判定 `rebooted`，即使本次开机计时已经超过前一次。标识相同时，结合退出标记和连续的开机计时判定服务退出或中断；如果计时与标识冲突，记录证据冲突并按退出标记降级。一侧缺少标识时退回计时判据，明确回退支持 `rebooted`；计时继续增长时，仅依据退出标记或缺失证据进行分类。同会话的睡眠和休眠继续按计时差判断。Windows 快速启动、休眠恢复与完整重启分别验证。 [Microsoft Fast Startup](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail)

### 5.2 采样器

- 服务端配置加载后先准备记录器和采样器，再等待网络。硬件接口未就绪时，相应通道标为缺失，其他通道正常记录。网络初始化期间收到退出信号或后续监听失败时，同样走记录器关闭流程。采样、阻塞式硬件读取、文件 IO 和压缩都避开异步请求工作线程。
- 每条已认证的实时连接维护独立租约。请求间隔夹在最小间隔和空闲间隔之间，并按请求周期计算租约到期时间。请求周期先限制到 60 秒再计算，租约取 max(10 秒, 2 × 请求周期 + 5 秒)。断开立即清除；客户端暂停或离开监控页时停止续约，到期后回落。旧客户端未提供间隔时使用该连接已有周期，首次缺省使用默认实时周期。历史同步连接无需租约。
- 采样器订阅租约变化，新租约或更细的周期会重算下一次采样时间。慢采样跳过已错过的定时点，恢复后继续正常周期。一次采样完成后生成不可变快照，实时读取返回最近快照。首个快照尚未完成时，短暂等待，超时返回可重试状态。
- 实时响应保留现有 Status 结构，在 SystemInfo 增加可选样本身份和周期。时间戳取采样时刻。未变化的样本重复读取时保持相同身份。网络速率按同一网卡相邻有效计数器和真实经过时间计算，首样本、计数器重置及跨缺口的速率记为缺失。实时响应以可选有效位表达缺失，旧客户端的整数速率字段沿用零值兜底。设备字段每次完整刷新，读取失败时清除上次残留值。

### 5.3 记录器

- 记录通路使用有界 FIFO（初始 256 条）。实时快照独立发布；队列满时跳过待入队记录，保留首尾丢失时间和序号，恢复后补记缺口。队列正常消费时，一次采样对应一条 WAL 记录。Tokio 的 watch 只保留最近值，适用于实时快照或设置通知。 [Tokio watch](https://docs.rs/tokio/latest/tokio/sync/watch/) · [Tokio mpsc](https://docs.rs/tokio/latest/tokio/sync/mpsc/)
- 记录器单写者管理追加、封存、换日和保留。控制通路按采样序号栅栏处理启停和关闭，队列满时仍可交付控制命令。封存期间可缓存有限数量的新采样，按同一过载规则处理。
- WAL 批量写入，正常运行至多每 30 秒同步一次；封存、停录和正常退出前提前同步。干净退出先停止采样、排空队列，再封存待写数据并持久化退出标记。存储异常或超过关闭期限时报告失败；下次启动依据可恢复的数据判断空缺。
- 每个块达到封存时间、记录点数或字节上限之一即封存；跨日、时钟分段和通道目录变更时也结束当前块。停录继续服务实时请求。重新开启后从新段开始，记录中间空缺。

## 6. 空缺与时钟调整

统一使用半开区间 [from, to)。所有持续时间比较使用有符号差值。启动时从索引找最近一次记录活动或持久化标记，跨多天也可定位；按文件的发布顺序和样本身份取证，墙钟日期只负责展示和定位。

| 代码 | 显示 | 证据 |
| --- | --- | --- |
| disabled | 记录已关闭 | 已确认的关闭标记与恢复记录 |
| storage | 记录写入失败 | 可确定的写入或同步失败区间 |
| recorder_overrun | 记录队列溢出 | 记录端发现采样序号存在跳过 |
| rebooted | 检测到重启 | 两侧有效的开机标识不同；缺少任一标识时，跨进程开机计时明确回退 |
| stopped | 服务已退出 | 跨进程且上次有正常退出标记，缺少明确重启证据 |
| interrupted | 服务中断 | 跨进程且上次缺少退出标记 |
| sleep | 睡眠或休眠 | 同一会话内 Δtick − Δawake ≥ 3 秒，墙钟与 Δtick 的差在容差内 |
| clock_jump | 系统时间调整 | 同一会话内墙钟增量与 Δtick 相差超过 3 秒 |
| stalled | 采样中断 | 时钟证据连续，实际间隔超过 max(3 × 预期周期, 10 秒) |
| unknown | 无记录 | 缺少足够的证据 |

- 周期切换按交接两侧较慢周期判定停顿。已知停录、写入失败、队列丢样和时钟事件独立于一般停顿阈值。多个证据可以保留，界面按明确的停录或记录故障、时钟事件与重启证据、一般停顿的顺序选主要原因。
- 缺口从上一可用点的覆盖终点开始，到恢复采样时结束。两个缺口只在彼此相接、原因一致且中间没有有效样本时合并。缺口记录在恢复日文件，索引保存实际起止时间，区间查询覆盖所有可能相交的归属日。保留策略可裁去超出可用范围的部分。
- 墙钟向前跳时，分段并标记跳过的正向区间。向后跳时，从新墙钟位置另开一段，继续记录；旧段仍保留。区间重叠时，较新段中已有证据的部分优先，缺少证据的部分可显示旧段；两段交界处断线。回拨事件作为点标记展示，图表跟随最新采样所属段。记录格式按写入顺序分配段号与同步游标，允许同一 UTC 日重新打开后追加。
- 正常短间隔内阶梯持有到下一点；跨段或遇到缺口时最多持有一个目标周期，并裁到缺口起点。最新点的展示延伸同样有界。传感器缺值只断开该通道。

## 7. 存储格式

### 7.1 日文件和包

数据目录持久化 store_id。日文件头包含魔数、格式版本、UTC 日和随机日代号。新建日文件时生成日代号；重开原文件时沿用，避免删除后重建导致旧游标指向新数据。服务端每个历史目录只允许一个写入进程。

| 文件或包 | 内容 |
| --- | --- |
| YYYY-MM-DD.rhh | 已发布日志，追加写入；提供稳定的包边界和文件偏移 |
| YYYY-MM-DD.pub | 日代号和已持久化的发布边界，带校验 |
| YYYY-MM-DD.wal | 未封存的样本、待发布的缺口与状态交接事件 |
| retention.json | 整个数据目录共用的保留台账和时钟状态，独立于所有日文件 |
| CATALOG | 目录版本、通道键、类型、单位和量化规则 |
| FRAME | 样本序号、采样时刻、目标周期、逐点时钟读数、有效位与原始列值；仅写 WAL，会话从文件上下文取得 |
| MARKER | 会话定义（会话 ID 和可选开机标识），或启动、退出、停录、恢复、时钟分段事件 |
| BLOCK | 目录版本、段号、会话引用、样本序号及时间范围、数量、最后样本的逐点时钟读数与压缩载荷 |
| GAP | 实际起止时间、原因、证据段号与来源事件 ID |
| ROLL | 可选小时汇总，首期保留包类型 |

`MARKER(Session)` 在每个物理文件内为引用到的会话保存完整 `session_id` 与可选 `boot_id`；同一会话跨 UTC 日或封存时，目标文件也必须先写入对应定义。`FRAME` 继承本 WAL 中最近一条会话定义，只写 `sample_seq`；会话交接事件和 `BLOCK` 用文件内定义包的起始偏移引用会话。块不跨会话。`ClockEvidence` 的存在位 0–2 对应 `wall_ms`、`tick_ms`、`awake_ms`，保留位写零；墙钟用小端 i64，计时用小端 u64。`boot_id` 只在会话定义中保存，非空 UUID 按字符串对应的 16 字节顺序编码。按区间解码、尾部分页和同步时必须带上或先解析相应的定义；WAL 替换须保留未发布记录依赖的定义，并重写其中引用的本文件偏移。未定义或无效的会话引用视为损坏。去重与回放始终用 `(session_id, sample_seq)`，不用文件偏移或墙钟作为样本身份。封存后只保留块末样本的完整逐点时钟证据；恢复时结合会话定义或事件取证。

包头为 tag u8、payload_len u32 LE，随后是载荷与 CRC32C u32 LE，校验涵盖包头和载荷。读取前检查长度和边界。zstd 帧校验可另行启用，包层仍统一校验。未知文件版本提示升级；中段损坏或无法判定的损坏保留原文件并报告。仅写入者在恢复时可以修剪确认未提交的断尾，普通查询只读取到发布边界。 [Zstandard 格式](https://github.com/meta/zstd/blob/dev/doc/zstd_compression_format.md)

### 7.2 通道与块编码

| 通道键 | 源单位 | 类型与量化 |
| --- | --- | --- |
| cpu.usage, gpu.usage | 百分点 0–100 | u16，乘 100 |
| cpu.temp, gpu.temp | °C | u16，先加 100 再乘 100 |
| cpu.power, gpu.power | W | u16，乘 10 |
| mem.used, mem.total, gpu.mem.used, gpu.mem.total | B | u64 |
| net.rx.rate, net.tx.rate | B/s | u64 |
| uptime | s | u64，仅供展示，重启判定用时钟证据 |

量化值舍入到最近整数，非有限值或越界值标为缺失。每列位图是缺失值的唯一表示。目录版本随写入发布，块引用本文件中更早的 CATALOG。内存占比用同一点的 used / total 计算；累计网络字节保留在实时响应里。

块内时间基准为最早采样时间。按顺序编码时间偏移、样本序号增量和目标周期，再按列写有效位图与有效值。量化、字节和秒值首个有效值用无符号 varint，后续差值以 i128 计算后 zigzag 编码；缺失值跳过且保留上一个有效值做差分基准。速率直接写无符号 varint。解码验证位图、值域、计数、目录版本和末尾边界，限制 zstd 输出及窗口。

每块最多 2,048 点，压缩包最多 128 KiB，解压输出最多 512 KiB；超限时按样本边界拆块。块覆盖描述采样时刻范围，用于查询索引；阶梯的时间覆盖由查询结合邻接样本与缺口计算。块可在同一天分多段，跨块可有缺口。

### 7.3 封存和恢复

1. 读取并同步待封存 WAL。将样本和关联的 MARKER/GAP 写入 .rhh，按稳定的样本身份和事件 ID 标明已提交内容。
2. 同步 .rhh 后，持久化新的发布边界并通知查询端。边界文件用同目录临时写入、同步和替换。网络只读取边界以内的完整包；被公开的偏移持续有效，直到整天淘汰或日期代号作废。
3. 重建 WAL 时写同目录临时文件，先同步再替换。临时文件提交失败时保留旧 WAL。跨日只清理已经提交的 WAL。发布推进应与尾部读视图切换在同一临界区生效。旧 WAL 仍含已发布记录时，尾部视图只暴露未发布后缀，并更新读视图世代，详见 §10.2。
4. 启动时先验证发布边界及其以内的完整前缀，恢复块索引、已提交样本范围和事件 ID。健康前缀之后的未发布尾部由写入者移除，用保留的 WAL 回放。WAL 若仍含已发布样本或事件，按身份跳过。发现边界文件或已发布区损坏则报告该日不可用，保留证据并停止沿用该日游标。新建日的初始边界指向文件头末尾，并在写入、发布首批内容前持久化。

文件数据同步与重命名采用平台支持的持久化原语。崩溃保证以实际文件系统和同步结果为边界；进程强杀与系统断电分别验收。正常运行时潜在丢失包括尚未同步的 WAL 和队列中的样本。 [Windows 文件替换](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)

### 7.4 索引、汇总与保留期

- 启动恢复最近活动证据，按需建日索引。索引包含块偏移、时间范围、发布边界和归属该日的 GAP 边界。长缺口查询遍历所有可能相交的归属日，包括查询范围之后的日期。首期以块查询为基线。后续 ROLL 按有效覆盖毫秒写入加权和及覆盖时长，只在完整、无缺口且无时钟重叠的小时使用；其余边界解块。
- 默认保留含今天在内的最近 30 个 UTC 日，容量目标 512 MiB，两项独立生效。按整天淘汰，含 `.rhh`、`.pub`、`.wal` 与附属文件。当前开放写入的日期优先保留。待删除文件计入占用；若活跃日的下一次追加将超容量，停止追加并报告存储状态，换日或空间恢复后重试并补记缺口。
- 日被删除或代号失效后返回可识别错误，客户端刷新目录，已持久化的缓存仍受客户端自己的保留策略管理。

### 7.5 保留台账与删除事务

`<history.dir>/retention.json` 与 `store_id` 绑定，由记录器维护。首版含以下字段。

| 字段 | 内容 |
| --- | --- |
| version, store_id | 台账格式版本和数据目录标识 |
| age_cutoff_day | 已提交的年龄清理边界，排他 UTC 日；用于判断历史请求状态 |
| capacity_evicted | 因容量清理的 UTC 日、被删日代号及当时可用的数据与缺口覆盖区间 |
| pending_deletions | 待删 UTC 日、日代号、原因和覆盖区间；年龄批次另带拟提交的截止日 |
| clock | 最后可信时钟基准，以及可选的暂停事件 ID 和检测时的墙钟 |

- 用同目录临时文件、同步、替换持久化台账。维护任务先在索引停止新读并持久化删除意图，再等待读取完成后删除对应日代号的文件。删除成功后提交淘汰证据并移除待删项。提交删除意图失败时恢复该日可读状态。删除或结算失败时保留待删项，未删文件继续计入磁盘占用，重启时恢复。如果该日已换代，仅结算旧代号。当前仍可用的新一代日文件及本地已缓存的有效数据优先展示。
- 历史查询按已提交的年龄边界和容量淘汰区间报告过期。年龄边界记录已经执行的策略；新一轮删除用当时有效的配置和可信时间重新计算。容量清理只对有淘汰证据的覆盖区间报过期。待删文件仍存在时报告清理中。已有数据目录的台账缺失、损坏或 `store_id` 不匹配时报告异常并暂停自动删除，在恢复前只使用可验证的淘汰证据。新建数据目录时初始化空台账。

### 7.6 恢复年龄清理

- 检测到时钟跳变时，保留最后可信时钟基准，把带随机事件 ID 的暂停状态写入台账；服务重启后继续暂停。服务在仍可确认是同一次开机时用开机计时推算可信墙钟，回到容差内则持久化恢复；跨开机且无法验证该基准时继续等待本机确认。容量清理继续按已用空间运行。
- 保留本机与远程两条确认路径。本机管理员核对服务器当前 UTC 时间后，将包含 `store_id` 和当前 `event_id` 的 JSON 写到数据目录 `clock.ack`，建议先写临时文件再重命名。两个标识和路径由服务器日志给出。服务在维护循环及启动时检查该文件，目录权限限制为服务账户与本机管理员。
- 远程确认仅开放给通过服务端指纹验证和扩展登录的历史管理员。客户端并排显示服务器 UTC 与本机 UTC，提示先通过可信时间源核对并纠正服务器时钟；客户端时间只供参考，不参与服务端取证。`GetSettings` 为当前连接提供与 `store_id`、`event_id` 和服务器读数绑定的短期确认凭据（最长 2 分钟，按单调时钟计时）；断线、过期或检测到新跳变后必须刷新并重新确认。
- 记录器串行处理跳变、确认和清理。两条路径都只接受匹配当前存储实例和暂停事件的确认。远程提交须额外验证确认凭据和权限，并在采纳前用单调计时复核服务器墙钟自展示后未再次跳变。处理时重读墙钟，以当前服务器读数建立可信基准。先持久化基准并清除暂停，再移走本机确认文件或返回远程成功，最后按新时间调度到期检查。写入失败时保持暂停；本机路径可重试，远程路径返回当前状态。并发或重放只可能结算一次；请求超时先重读 `GetSettings`，不自动重发确认。

## 8. 容量与性能预算

以下是验证起点。按 13 个通道和每条 WAL 约 88–144 B 粗估（会话定义与包头等开销以实际编码为准），全天 5 秒采样的未压缩写入量约 1.5–2.5 MB，全天 1 秒采样约 7.6–12.4 MB。这个量是累计写入，不是日归档体积。会话 UUID 和开机 UUID 在同一次会话内重复，不是逐点随机；按会话提取的直接收益是减少 WAL 体积与写入量。封存块原本就只保存块级身份和末样本时钟证据，归档收益不按每点 32 B 推算。默认 300 秒内在 5 秒、1 秒、250 ms、100 ms 周期下分别约有 60、300、1,200、3,000 个点；100 ms 时至少触发一次点数封存。WAL 的瞬时占用还应计入封存积压和替换临时文件。

封存首版从 zstd 级别 3 开始，以真实数据比较 3、6 和 19 的压缩比、CPU 时间及磁盘写入延迟，记录空闲、1 秒和最细周期三组结果，再确定默认值。首次同步容量按实测封存体积和预取天数计算。查询基线测量一小时、三天与三十天的冷读、热读以及拖动过程中取消陈旧请求的成本。全量同步和解块均限制并发及内存；持续压缩和硬件读取应纳入 CPU 与独显唤醒测试。

## 10. 历史协议

### 10.1 能力发现与身份

ClientHello 增加可选支持版本，ServerHello 增加可选的历史协议版本、安装实例 ID、服务端 Ed25519 公钥和握手签名。签名覆盖上下文标识、双端临时公钥、实例 ID、客户端提供的版本和服务端选择的版本，使用确定且无歧义的编码。长期私钥存于历史数据目录之外。客户端核对已固定的指纹，并在提交客户端认证凭证前验证签名。首次连接支持历史的服务端时优先使用部署时提供的指纹；未配置指纹时按 §13.3 的登录确认条走首次信任。首次确认的可信度取决于所用的指纹核验渠道。主连接和同步连接都验证同一身份与受信能力。在协商历史能力的连接中，客户端登录签名同时绑定服务器挑战和握手摘要，服务端验证该扩展签名后才开放历史请求。旧连接继续使用原登录签名。现有 1 KiB 握手上限双方统一检查。设计参照握手签名覆盖协商内容的做法。 [RFC 8446 §4.4.3](https://www.rfc-editor.org/rfc/rfc8446.html#section-4.4.3)

初次连接无历史能力的旧服务端时，保留原有实时监控。旧客户端可继续向新服务端发原有请求。已经固定身份的地址若丢失签名、能力异常或指纹变化，暂停连接并提示核对；已有缓存仍可离线查看。实例 ID 用于安装归属，缓存实际按公钥指纹及 store_id 分区。历史目录重建时换 store_id；服务端身份变化走单独的重新绑定流程。

### 服务端身份文件与恢复

- 初次启用历史协议前，由本机管理员通过部署命令生成身份；命令只创建不存在的身份，不覆盖现有文件，也不输出私钥。固定路径为配置文件所在目录的 `identity/server-identity.v1`，与历史目录分离，保存格式版本、安装实例 ID 和 Ed25519 私钥材料。先在同一受保护目录写临时文件、同步，再以不覆盖方式发布；生成和读取均拒绝通过链接或重解析点访问。服务账户只读，管理员可管理；Windows ACL 在创建时限制访问，Unix 由受控属主和目录权限保护。管理员可从本机部署命令或启动日志取得公开指纹，并单独备份身份文件。
- 身份未配置，或文件缺失、损坏、权限校验失败时，不自动生成替代身份，不开放历史协议、远程设置或远程时钟确认；本地记录和旧客户端实时模式保持可用，服务端报告明确的身份状态。已固定身份的客户端不得静默回退。能恢复备份时优先恢复原文件；私钥确认丢失或需轮换时，由本机管理员显式生成新身份并通过可信渠道提供新指纹。
- 客户端对身份变化提供独立的「重新绑定服务器」操作，展示目标地址、旧指纹和候选新指纹，要求通过可信渠道核对后再次连接，验证仍是同一新指纹且握手签名、客户端登录均成功，再原子替换固定记录。取消、验证失败或保存失败时保留旧绑定；旧缓存按旧指纹保留供离线查看，不自动并入新分区。`store_id` 变化而服务端公钥未变时，新建缓存分区，不触发身份重新绑定。

### 10.2 请求和分页

| 请求 | 返回及约定 |
| --- | --- |
| HistorySummary | 固定大小的元数据，含 store_id、数据时间范围、最新样本身份、已用空间、存储状态及年龄保留边界 |
| HistoryDays { range, cursor } | 分页返回需求区间对应的日条目、待清理状态或台账确认的淘汰区间。日条目含 UTC 日、日代号、发布终点、数据范围和缺口范围。纳入缺口范围可能与需求区间相交的归属日 |
| HistoryBlocks { day, day_id, after, through } | 复制该日给定发布边界内、从 after 开始的连续完整包，返回实际下一偏移及是否到达 through。首批提供日文件头；CATALOG、BLOCK、GAP、MARKER 都沿同一游标获取 |
| HistoryTail { cursor } | cursor 缺省时打开当前 WAL 尾部快照；以 { wal_generation, offset, through } 分页返回未封存样本及待发布事件，包含目录版本和样本身份 |
| GetSettings | 设置、修订、管理权限、运行状态及可选的时钟暂停事件，含 `store_id`、`event_id`、检测时与当前的 UTC 时间；仅管理员取得短期确认凭据 |
| AckClock { store_id, event_id, confirmation } | 独立于设置写入，按 §7.6 确认恢复年龄清理；返回当前时钟状态，未获授权、事件变更、凭据失效或落盘失败分别报告 |
| SetSettings { expected_revision, history } | 条件写入历史设置并返回新快照；修订冲突返回当前快照 |

after 是下一包起始字节偏移，through 是目录页给出的排他上界。快照读取时允许日文件继续追加，页内游标严格前进。目录游标顺序固定并能在目录失效时重建；已经同步的数据以日代号和偏移续传。保留删除、日代号变化、格式不支持、缓存或服务端损坏分别返回结构化状态。客户端以协商版本处理降级，旧服务端的 JSON 错误文本仅供诊断。

尾部游标的 `wal_generation` 是服务器分配给当前 WAL 读视图的随机 128 位代号；`offset` 和 `through` 是 u64 字节偏移，必须落在完整包边界。首批固定 `through` 为当时最后一个完整包之后的偏移；正常追加维持当前世代，各页沿用该上界。封存改变可读起点、替换或截断 WAL、换日及服务重启时均换代。服务端在同一读视图上检查世代和边界并读取该页；世代不匹配返回 `TailRestartRequired`。客户端以空游标打开新尾部，再刷新日目录并补拉已发布的块。此顺序覆盖打开新尾部前已移出 WAL 的记录，包括换日时封存到前一天的块。分页期间再次换代则重新执行此流程。

### 10.3 传输预算与连接管理

- 历史连接接收的加密帧体上限为 1 MiB，含认证标签，长度前缀另计。分页以序列化后的 JSON 字节数预算，计入 base64、元数据和加密开销。目录、块和尾段都受分页限制；至少一个合法最大块和必要元数据能装进一页。服务端在加密前校验最终大小，超限时返回有界错误并避免原消息进入发送队列。
- 请求仍使用 10 KiB 上限；旧实时连接原有响应预算保持兼容。读帧限长后再分配，基础校验失败、超时或取消中途往返后关闭连接再建立，避免下一请求误读上一响应。
- 独立历史连接使用主会话的目标与身份验证结果，同一连接顺序执行一个请求，和实时轮询各自调度；服务端限制在途历史请求及查询并发。连接占用服务端现有额度，遇到上限时退避并让实时请求优先。服务端现有整体连接超时仍有效；客户端按连接重建后继续同一页。同步空闲 60 秒或切换主机时主动关闭连接。

## 11. 本地缓存

本地使用系统应用数据目录的 `RemoteHelper/hosts/<fingerprint>/<store_id>/`。每个分区保存主机信息、历史覆盖和日文件。日文件与服务端格式相同，客户端原样保存已验证的压缩包。每个日文件只持久化连续前缀，从文件头的日代号、有效包与末尾偏移恢复游标。任何单独写入的清单均可重建；推进持久游标前先同步数据。缓存写入者按分区串行，查询读取已发布的本地前缀。

1. 登录后读取摘要和目录，按需比对各日的日代号和本地连续前缀。默认自动预取最近 7 天，可见区间优先调度，仍按天从缺失偏移读取。一个后调度的日可以先完成，其他日期仍保留原游标。短期尾部通过 HistoryTail 优先补齐。
2. 每页校验版本、日代号、包校验、偏移连续性和各尺寸限制后追加。断线时从最后有效偏移续传，收到重复页跳过已验证的相同字节。相同偏移内容不符时隔离该日并重新验证目录。
3. 默认每 60 秒拉取增量。若过期或代号更换，刷新目录；较旧的本地版本保留供离线查询，新代号使用独立文件。当前代号同步后优先查询其重叠区间。
4. 客户端默认保留 30 天和 512 MiB，按天清理。服务端已淘汰的内容只要仍在本地就照常展示。本地缓存关闭时使用有上限的内存缓存，退出清空；主动请求本地保留范围之外的服务端历史也可走内存缓存。
5. HistoryTail 及实时采样只保留在内存。收到 `TailRestartRequired` 时重建正在分页的尾部快照，已展示的暂存点在封存数据或新尾部覆盖后按样本身份去重替换。离线打开按主机选取已固定的缓存，保留最后一份目录与同步状态。

## 12. 设置

### 12.1 服务端设置与权限

配置缺少 history 段时使用默认值。dir 相对 config.toml 所在目录解析，目录及管理员公钥仅由本机配置修改。`[history].admin_keys` 默认为空，保存与 `[web_panel].authorized_keys` 同格式的 Base64 Ed25519 公钥，修改后重启服务端生效。仅同时位于两份名单的已认证公钥有写权限。通过历史握手与扩展登录认证的客户端可查询历史。管理请求由服务端按已认证公钥检查授权；客户端仅在服务端指纹验证通过后发起管理请求。

~~~toml
[history]
enabled = true
dir = "history"
admin_keys = []
idle_interval_ms = 5000
min_interval_ms = 250
seal_interval_secs = 300
retention_days = 30
retention_bytes = 536870912
compression_level = 3
~~~

| 可在线设置项 | 校验 |
| --- | --- |
| enabled | 布尔值 |
| idle_interval_ms | 250–60,000 |
| min_interval_ms | 100–idle_interval_ms |
| seal_interval_secs | 60–3,600，同时受块的点数及字节限制 |
| retention_days | 1–3,650，0 关闭该限制 |
| retention_bytes | 16 MiB–16 GiB，0 关闭该限制 |

至少保留一种有效的淘汰限制。压缩级别由本机配置应用。远程变更按修订串行，先校验整个设置并以 toml_edit 更新读取到的当前配置，再写入同目录临时文件、同步并替换原文件。修订包含随配置一同提交的递增版本及规范化配置摘要，重启后保留一致性，检测进程外配置修改时报告冲突并要求重新加载。持久化成功后应用给运行时，记录器按采样序号处理停录与恢复，缩小保留范围会调度清理。响应区分配置已保存、记录器运行状态和清理进度；配置保存失败时仍使用原设置。请求超时先重读设置与修订再决定是否重试。

### 12.2 客户端设置

客户端偏好写入应用配置目录的 remotehelper/settings.json，与登录配置同级。默认启用缓存，缓存 30 天、512 MiB，连接时预取 7 天，增量间隔 60 秒，趋势图默认窗口 5 分钟。关闭自动预取后，在线仍可按可见区间请求历史。清除本地缓存时先暂停该主机正在运行的写入和查询，再清理日文件、游标与临时文件；下次同步从目录重建。

设置页只包含服务器历史和客户端缓存。服务端展示目录、占用、最早记录、权限与存储状态；客户端展示本地占用和同步状态。保留策略预计清理的范围在提交前提示，其余服务端配置由现有流程管理。权限和时钟暂停的具体呈现见 §13.3。

## 13. 趋势图

监控页继续使用现有趋势图。图表的可用范围来自服务端目录、本地缓存和实时尾部的并集。目录范围、已读区间、缺口原因与来源水位分别保存；范围可随淘汰收缩。跟随模式以最新采样为锚，历史拖动和缩放仍使用现有交互。UTC 时间戳在展示时按对应时刻换算本地时区。

### 13.1 查询与折桶

1. 后台查询取出视口涉及的完整时间桶，以及确定桶边缘覆盖所需的相邻样本。完成聚合后再裁到视口。合并封存块、未封存快照和实时样本；先用稳定样本身份去重，再按已确认覆盖与时钟段处理重叠。封存数据和持久化缺口优先，尾段其次，实时样本用于覆盖尚待确认的尾部。已过期的服务端范围中仍显示有效本地数据。
2. 稀疏时绘制原始阶梯。长视口按 UTC 对齐的固定时间桶画时间加权均值，权重为采样在有效阶梯中占用的毫秒数。桶边界切分权重，缺口和缺值部分没有权重，跨缺口的同一桶分别画在连续的有效段内。这样在同一视口内，0.5 秒采样和 5 秒采样各自的影响按覆盖时长计算。悬停使用绘制结果，并标记均值周期和有效时长。
3. 复用现有阶梯绘制和悬停基础，聚合输入扩展为带有效区间、缺口与来源水位的数据。查询缓存键含主机、范围、桶尺寸和数据版本；拖动时可显示同一主机上一次有效结果，过时查询取消或丢弃。后台结果回到 UI 线程发布。

### 13.2 空白与状态

| 状态 | 判定与画法 |
| --- | --- |
| 记录空缺 | 有已确认的 GAP，断开阶梯并画斜线带，悬停展示原因与时长 |
| 尚未同步 | 目录表明可能有数据或缺口归属日，所需包尚未拉取；待取时显示点状底纹，离线或失败时显示实际状态 |
| 已过保留范围 | 有服务端保留边界或淘汰证据，且缺少可用本地数据；展示边界与说明 |
| 无记录 | 已确认该段无历史，或早于首次记录但仍处于保留策略的时间范围；用普通留白 |

顺序以合并后的有效样本和缺口为准，之后判定明确淘汰、所需包尚未拉取、已确认无记录。视口超出当前时间时按范围以外处理。暂停仅停止实时轮询。刷新间隔保留在窗口底栏，说明实时监控时它也参与服务端采样粒度计算；历史同步和离线浏览独立运行。

### 13.3 登录确认条与设置权限

- 首次连接支持历史的服务端，且本地没有预配置或已固定指纹时，先用服务端声明的公钥验证探测握手签名，再在现有登录页显示确认条，包含目标地址、完整的服务端公钥指纹（对 32 字节 Ed25519 公钥计算 SHA-256，以小写十六进制显示）、「复制指纹」「确认并连接」和「取消」。确认前关闭探测连接，等待用户通过可信渠道核对。确认后重连，核对探测时显示的同一指纹并验证本次握手签名，验证通过后继续客户端认证，登录成功且固定记录持久化后才启用历史同步与远程管理。取消后停留在登录页；重连时指纹变化则提示重新核对。
- 设置页显示当前登录用的 Base64 客户端公钥和「复制公钥」。服务端历史设置在无管理权限时只读，旁边提示「将此公钥加入服务端 config.toml 的 [history] 下的 admin_keys，然后重启服务端」。客户端缓存设置仍可操作。
- 年龄清理暂停时，设置页并排显示服务器与客户端当前 UTC 时间、暂停事件 ID 和本机 `clock.ack` 处理说明。有管理权限时提供「确认服务器时间并恢复清理」，明确提示清理可能立即开始，用户核对后才提交；无权限时只读。服务端日志提供本机确认所需的目录和标识。

## 14. 开发顺序

1. **服务端记录。** 共享格式、含开机标识的时钟证据、有限记录队列、WAL 恢复、存储故障、持久化保留台账与本机时钟确认。以真实采样完成 24 小时测试，为块体积、CPU、磁盘与独显唤醒建立基线。
2. **协议与缓存。** 服务端身份初始化、握手验证、登录确认条与重新绑定、历史能力、分页和按日续传；验证旧客户端兼容、旧服务端降级和全量同步时的实时延迟。
3. **趋势图与设置。** 离线查看、缺口和覆盖渲染、最近尾段合并、管理权限提示、配置持久化及远程时钟确认。以长范围冷读实测决定小时汇总的优先级。
4. **后续优化。** 小时汇总、字典压缩、设备通道扩展与受控清理工具。

## 15. 验收用例

| 分组 | 验收用例 |
| --- | --- |
| 采样 | 多连接交替请求；长周期租约；暂停、切页、断线；快照重复读取；网络速率除以实际时长；传感器读失败 |
| 格式 | 原始记录往返；会话定义有无开机标识；跨日、多会话、WAL 替换和尾部分页后身份不变；拒绝未定义会话引用；量化边界、非有限值、u64 差分、缺失位图、未知版本、CRC 错误、解码尺寸限制 |
| 恢复 | 写 WAL 中断；写块中断；块落盘后发布前中断；发布后 WAL 未替换；重复回放 GAP；跨天切换；进程强杀及独立的断电测试 |
| 时钟 | 旧开机运行 20 秒就重启且新开机已运行 30 秒时，两个有效标识不同应判为重启；同一开机服务重启、标识缺失或冲突、休眠和快速启动；多天空缺、前跳和回拨、两种事件重叠 |
| 保留与确认 | 年龄和容量删除后重启仍能查询淘汰证据；删除意图提交前后及文件删除后中断；台账缺失或损坏暂停清理；当日换代保留新文件；时钟暂停跨重启、自动恢复、本机和远程并发确认、远程无权限、旧事件、凭据过期、确认前时钟再次跳变、落盘失败与请求超时后重读状态 |
| 同步 | 优先拉取后面的日期后回补更早日期；空缺归属日在需求区间外；帧边界、重复页、并发淘汰、当日重建；正常追加期间尾部游标可用；封存、换日及重启后旧游标返回 TailRestartRequired；新尾部打开前已封存的块可补齐，交接无丢样或重复 |
| 身份与设置 | 新旧版本交叉连接；身份初始化不覆盖、权限错误和私钥丢失不自动换钥；首次指纹核对、取消、重连时指纹变化；备份恢复、显式重新绑定和旧缓存离线可用；删除历史目录与重建；未授权用户看到可复制的公钥和授权步骤，配置公钥并重启后取得写权限；并发修订和磁盘只读 |
| 查询与界面 | 5 秒内的十个 100% 样本和之后 5 秒内的一个 0% 样本应得 50% 均值；同桶内缺口裁切；回拨重叠；离线状态；长范围查询期间重复拖动与切换主机 |
